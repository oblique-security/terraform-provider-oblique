# Oblique provider

The Oblique provider manages identity and access resources in [Oblique](https://oblique.security). Use it to configure integrations, users, teams, and groups.

## Example usage

```terraform
# Configure the Oblique provider. The endpoint points at your Oblique
# deployment. `repo_url` and `repo_dir` are optional; when set, the values
# are stamped onto every Terraform-managed resource so operators can find
# the source of truth for any object Oblique reports as TF-managed.
provider "oblique" {
  endpoint = "https://us.oblique.security"
  api_key  = var.oblique_api_key
  repo_url = "https://github.com/example/infra"
  repo_dir = "/oblique"
}

variable "oblique_api_key" {
  type      = string
  sensitive = true
}
```

## Schema

### Required

- `endpoint` (String) Base URL of the Oblique instance used. This depends on your tenant's [region](https://docs.oblique.security/admin/regions/) and should be either `"https://us.oblique.security"` or `"https://eu.oblique.security"`.

### Optional

- `api_key` (String, Sensitive) API key used to authenticate against the Oblique API.
- `repo_dir` (String) Subdirectory inside `repo_url` that holds the Terraform configuration. Optional; only meaningful when `repo_url` is set.
- `repo_url` (String) URL of the VCS repository where the Terraform configuration for the managed resources lives. When set, it is recorded on every Terraform-managed resource so operators can trace the source of truth.

## Common scenarios

### Basic setup

Configure the provider, connect to Okta and Google Workspace, and set up admin users.

```terraform
# Basic setup of a fresh Oblique instance. This is the starting point for a
# new deployment — no pre-existing resources are required, only an API key
# for the Oblique instance and credentials for any integrations you want to
# connect.
#
# After running this, you'll have a provider configured, integrations to
# Okta and Google Workspace, and an admin user designated as the account
# owner. From here you can proceed to the team groups, attribute and
# reporting based groups, and service catalog scenarios.

terraform {
  required_providers {
    oblique = {
      source  = "registry.terraform.io/oblique-security/oblique"
      version = "~> 0.1"
    }
  }
}

variable "oblique_api_key" {
  type      = string
  sensitive = true
}

provider "oblique" {
  endpoint = "https://us.oblique.security"
  api_key  = var.oblique_api_key
  # repo_url and repo_dir are recorded on every Terraform-managed resource
  # so operators can trace each object back to the configuration that owns
  # it. Both are optional — set them to point at the repository where this
  # Terraform configuration lives.
  repo_url = "https://github.com/example/infra"
  repo_dir = "/oblique"
}

# Connect Oblique to Okta for user provisioning and group sync
resource "oblique_integration" "okta" {
  display_name = "Okta"
  okta = {
    client_id       = "0oa1gjh63g214q0Hq0g4"
    client_secret   = var.okta_client_secret
    domain_base_uri = "https://your-org-admin.okta.com"
    display_name    = "Okta"
  }
}

# Connect to Google Workspace
resource "oblique_integration" "google" {
  display_name = "Google"
  google = {
    domain = "example.com"
  }
}
```

### Team groups

Create a team group — a manually-managed collection of users that can be used anywhere an `oblique_group` can.

```terraform
# Create a team group. Team groups are explicit, manually-managed
# collections of users that can be used anywhere an oblique_group can (as
# an entitlement subject, listing role policy, etc.).
#
# This scenario assumes the provider is already configured (see the
# basic_setup scenario) and that users have been synced into Oblique from
# an identity provider — they are looked up here via data sources.
#
# See https://docs.oblique.security/admin/groups/ for background on the
# different kinds of groups.

data "oblique_user" "janedoe" {
  email = "janedoe@example.com"
}

data "oblique_user" "kevinsmith" {
  email = "kevinsmith@example.com"
}

# Create a team and assign members and owners
resource "oblique_team" "engineering" {
  display_name = "Engineering"
}

resource "oblique_team_member" "janedoe" {
  parent = oblique_team.engineering.name
  member = data.oblique_user.janedoe.name
}

resource "oblique_team_member" "kevinsmith" {
  parent = oblique_team.engineering.name
  member = data.oblique_user.kevinsmith.name
}

resource "oblique_team_owner" "kevinsmith" {
  parent = oblique_team.engineering.name
  owner  = data.oblique_user.kevinsmith.name
}
```

### Attribute and reporting based groups

Create dynamic groups that match users based on attributes from an integration or on reporting lines in the directory.

```terraform
# Create dynamic groups that match users based on attributes synced from
# an integration or based on reporting lines. Users are
# added automatically as their attributes or reporting lines change.
#
# See https://docs.oblique.security/admin/groups/ for background on the
# different kinds of groups.
#
# Pre-existing resources required:
#   - An `oblique_integration` named "okta" (the source of user attributes)
#   - An `oblique_user` with email "kevinsmith@example.com" (the root of
#     the reporting-line group)
#
# These would typically be created by the basic_setup scenario and your
# identity provider sync.

data "oblique_integration" "okta" {
  name = "integrations/okta"
}

resource "oblique_group" "engineering" {
  display_name = "Engineering Employees"
  attributes = {
    match = [
      {
        user_attribute = {
          integration = data.oblique_integration.okta.name
          key         = "department"
          value       = "Engineering"
        }
      },
    ]
  }
}

# Groups can match on multiple attributes (AND logic)
resource "oblique_group" "engineering_contractors" {
  display_name = "Engineering Contractors"
  attributes = {
    match = [
      {
        user_attribute = {
          integration = data.oblique_integration.okta.name
          key         = "department"
          value       = "Engineering"
        }
      },
      {
        user_attribute = {
          integration = data.oblique_integration.okta.name
          key         = "userType"
          value       = "Contractor"
        }
      },
    ]
  }
}

data "oblique_user" "kevinsmith" {
  email = "kevinsmith@example.com"
}

# Groups can also be based on reporting lines
resource "oblique_group" "kevinsmiths_organization" {
  display_name = "Kevin Smith's Organization"
  reporting = {
    manager          = data.oblique_user.kevinsmith.name
    include_indirect = true
  }
}

resource "oblique_group_owner" "kevinsmiths_organization" {
  parent = oblique_group.kevinsmiths_organization.name
  owner  = data.oblique_user.kevinsmith.name
}
```
